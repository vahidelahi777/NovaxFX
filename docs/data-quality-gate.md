# Data Quality Gate

**Module:** `src/novax/dataquality.py` · **Owner:** Data Quality Auditor
**Closes:** Phase 0.5 High #6/#7 surface + the "no backtest without a data-quality report" principle.

> **Fail-closed:** no backtest result is accepted unless the dataset passes this gate. A high-severity failure fails the report. Garbage data is the cheapest way to manufacture a fake edge.

## Checks

| Check | Severity | Fails when |
|---|---|---|
| `non_empty` | high | zero bars |
| `monotonic_timestamps` | high | not strictly increasing (out-of-order) |
| `no_duplicate_timestamps` | high | duplicate `ts` present |
| `valid_bid_ask` | high | any `ask < bid` |
| `no_negative_spread` | high | any negative spread |
| `spread_outliers` | medium | spreads beyond `spread_z_max`σ (default 8) |
| `coverage` | high | open-hours coverage < `min_coverage` (default 0.995) |
| `intra_session_gaps` | medium | gap > 1.5× timeframe within open hours |
| `no_closed_market_data` | high | bars present when market is closed (weekend/holiday) |

Coverage and closed-market checks use the **DST-correct `MarketCalendar`**, so weekend/holiday boundaries are correct year-round.

## Report schema

```python
@dataclass(frozen=True)
class CheckResult:
    name: str
    passed: bool
    detail: str
    severity: str            # high | medium | low

@dataclass(frozen=True)
class DataQualityReport:
    symbol: str
    timeframe: str
    n_bars: int
    checks: tuple[CheckResult, ...]
    @property
    def passed(self) -> bool          # all HIGH checks pass (fail-closed)
    def failures(self) -> list[CheckResult]
```

## Pass/fail rule

`report.passed` is **True only if every high-severity check passes.** Medium checks (spread outliers, intra-session gaps) surface for review but don't auto-fail; promote to high per instrument once thresholds are calibrated. This is deliberately strict on the defects that fabricate edges (gaps, contamination, bad quotes) and advisory on the noisier ones.

## API

```python
run_data_quality(symbol, timeframe, bars, *,
                 min_coverage=0.995, spread_z_max=8.0,
                 calendar=DEFAULT_FX_CALENDAR) -> DataQualityReport
```

## Example report (generated by the shipped code)

Input: 10 hourly EUR/USD bars on a Wednesday + 1 contaminating Saturday bar.

```
symbol=EUR/USD tf=1h n_bars=11 PASSED=False
  [PASS] monotonic_timestamps     (high  ) — timestamps strictly increasing
  [PASS] no_duplicate_timestamps  (high  ) — 0 duplicates
  [PASS] valid_bid_ask            (high  ) — 0 ask<bid bars
  [PASS] no_negative_spread       (high  ) — 0 negative spreads
  [PASS] spread_outliers          (medium) — 0 bars beyond 8.0σ
  [FAIL] coverage                 (high  ) — coverage=0.1429 (>= 0.995)
  [FAIL] no_closed_market_data    (high  ) — 1 bars while market closed (weekend/holiday)
```

The Saturday bar trips `no_closed_market_data`; the short window trips `coverage`. `PASSED=False` ⇒ no backtest may run on this dataset.

## Acceptance criteria

- [x] Report covers coverage, gaps, duplicates, monotonicity, bid/ask, abnormal spread, closed-market contamination.
- [x] Fail-closed on high-severity checks.
- [x] Uses DST-correct calendar for coverage/closed checks.
- [ ] (Phase 1) cross-source delta check (OANDA vs Dukascopy) and known-tail-event presence (CHF 2015, JPY 2024), once data is ingested.

## Implementation notes

The expected-bar coverage walk is O(bars) per check; fine for validation runs, not for hot loops. When ingestion lands, run the gate once per dataset version and store the `DataQualityReport` alongside the data hash in provenance — a backtest references the passing report by hash, making "no backtest without a passing report" mechanically enforced.
